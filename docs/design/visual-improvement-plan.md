# Visual Improvement Plan

Status reference for improving the game's visual elements across sessions. Reviewed 2026-08-13 against the current prototype. Pick up at the first unchecked item in the lowest unfinished tier, and keep the progress log at the bottom current.

## North Star (user directive, 2026-08-14)

> Everything should resemble a highly polished 1990s/early-2000s illustrated strategy game rendered with modern lighting. Shapes should be chunky and readable at 1080p. Avoid photorealism. Effects should be exaggerated but short-lived. Use warm highlights, dark ocean blues, creamy foam, heavy black cannon smoke, and bright orange fire.

Direction change behind it: the game is fun, so the goal moved from "prototype visuals" to "polished enough to share with a friend." A concept image (AI-upscaled from a real screenshot; user's copy at `C:\Users\roder\Downloads\visual-goal.png`) is the mood target — treat it as a **palette and richness** reference (deep blues, dense creamy foam, warm gold UI) rendered at our stylized fidelity, not a literal texture-fidelity target. Consequence for the constraints below: the procedural-only rule is now *soft* — assets are on the table where procedural is weakest (a segmented stylized ship model, one characterful UI font), pending an explicit user decision per exception. Water, sky, effects, and UI structure stay procedural.

## Guiding Constraints

These come from the design brief (`docs/design/pirate-game-design-principles-and-expansion-brief.md`, section 17) and the project's scope discipline:

- Target look: colorful, campy, early-2000s retro. Low-poly, bold silhouettes, painted/stylized feel, modern resolution, tasteful modern lighting.
- Everything stays procedural by default: no asset store models, no texture pipeline, no external dependencies, GDScript only. (Softened 2026-08-14 — see North Star above; exceptions need a user decision.)
- Readability improvements outrank pure polish. Playtest 0002 flagged projectile tracking, speed reference points, and target visibility as real gameplay problems visuals can help solve.
- The smoke test (`tools/run_smoke_test.ps1`) must keep passing after every visual change. Note it runs Godot in `--script` mode, and — correcting an earlier belief in this doc — autoloads ARE instanced there (verified 2026-08-13 by dumping the root's children: `GameSession` and `OceanWaveField` are live). Keep the defensive `get_node_or_null("/root/...")` pattern anyway for editor/tool contexts. The real trap is the opposite one: a live `GameSession` means a battle result firing mid-test changes `current_scene`, so the smoke test disables `auto_return_to_overworld` in every scene it instantiates.
- Verify visual changes by looking at them, not by reasoning about settings: run `tools/ScreenshotProbe.tscn` to capture in-engine screenshots of any scene, then read the images. Example: `godot --path . res://tools/ScreenshotProbe.tscn ++ --scene=res://game/scenes/Overworld.tscn --prefix=overworld --out=C:/some/dir`. It briefly opens a game window (needs rendering; do not use `--headless`), saves three frames ~0.8s apart (compare them to judge motion), and quits itself. Two hard-won lessons already paid for: exponential fog and missing wave normals both looked fine in theory and wrong on screen.

## Current-State Findings (as of 2026-08-13 review)

1. **No `WorldEnvironment` in either scene.** `NavalBattle.tscn` and `Overworld.tscn` render against the default gray clear color: no sky, no fog, no glow, no tonemap. Consequences:
   - The finite ocean plane's edge is visible against gray void.
   - All combat effect materials (`MuzzleFlash`, `ImpactFlash`, `BurningFlame`, `MagazineExplosion`) use emission with energy multipliers 1.6–2.8, which does almost nothing without glow enabled.
   - Both `Sun` lights have shadows disabled, so ships read as floating stickers.
2. **Inconsistent ocean.** The battle scene uses `game/shaders/StylizedOcean.gdshader` (banded color, fresnel, whitecaps — a good retro start). The overworld uses a flat dark `StandardMaterial3D` plane. Two scenes, two different seas.
3. **Rigid ships.** `ShipVisualBuilder.gd` is a solid data-driven foundation (procedural hulls, sail types, 96x64 nearest-filtered flag textures). But ships do not bob, pitch, or heel; waves move under them while they sit still. Sails are flat quads (though `update_sail_trim` already animates trim). Sinking is an instant snap (`ShipCombatComponent._sink`: drop 0.5, roll 9 degrees).
4. **Effects are scale-lerped emissive spheres.** `TemporaryVisual.gd` only lerps scale — no alpha fade, no particles, no light flicker, no camera shake. `ShipVisualBuilder.set_fire_state()` is an empty stub, so fire severity (ADR 0007) has no on-ship visual expression.
5. **Damage overlay reads as a glitch.** A translucent black box scaled 102–104% around the hull stands in for battle damage.
6. **Debug-styled UI.** All HUD elements are `_draw()` calls with the default theme font. Fine for a prototype; the brief eventually wants illustrated UI.

## Tier 1 — Atmosphere Fundamentals

Biggest payoff, no new assets. Everything here is engine settings and one material extraction.

- [x] Create a shared `Environment` resource (`game/environment/CaribbeanEnvironment.tres`):
  - `ProceduralSkyMaterial` sky with a warm Caribbean palette (deep blue zenith, pale warm horizon, ocean-toned ground colors so the below-horizon band blends with the water).
  - Glow enabled so existing emissive effects finally bloom.
  - Exponential distance fog tuned so the ocean plane edge melts into haze (fog color matched to the sky horizon).
  - ACES tonemap plus a slight saturation push for the campy-postcard look.
- [x] Add a `WorldEnvironment` node referencing the shared resource to both `NavalBattle.tscn` and `Overworld.tscn`.
- [x] Enable sun shadows in both scenes (`shadow_enabled = true`), lower `light_energy` from 2.2 to ~1.8 to compensate for new sky ambient light, and extend `directional_shadow_max_distance` to cover the visible play area (battle 160, overworld 220).
- [x] Extract the battle ocean's `ShaderMaterial` into `game/materials/StylizedOceanMaterial.tres` and use it from both scenes, replacing the overworld's flat `StandardMaterial3D`. Bump the overworld plane subdivisions (24x18 → 96x72) so vertex waves are smooth at its 240x180 size.
- [x] Verify the smoke test still passes and eyeball both scenes in-game (confirmed via playtest screenshots after the tuning passes below).

Implementation notes (2026-08-13): new `.tres` files are referenced by path without UIDs; Godot will assign real UIDs on next editor open, which may rewrite the `ext_resource` lines — that churn is expected and safe to commit. Hand-authored UID strings trigger "invalid UID" warnings, which is why they were left off.

Tuning knobs after first look: fog is depth-mode — `fog_depth_begin`/`fog_depth_end` set where haze starts/saturates and `fog_density` is its max opacity (exponential fog was tried first and rejected: it hazes every distance and reads like "peering through clouds"). Other knobs: `glow_intensity` (effect pop; keep `glow_bloom` at 0 or the pale water blotches smear), `ambient_light_sky_contribution` (0.7; raise toward 1.0 to flatten, lower to deepen sun contrast), `tonemap_white` (highlight headroom), sun `light_energy`. If the whitecap patches on the water still read as soft clouds, raise `whitecap_threshold` in `StylizedOceanMaterial.tres` toward 0.9 to shrink and tighten them.

## Tier 2 — A Living Sea, Ships That Sit In It

Directly serves "make the little boat sail feel good" (Milestone 0's success condition).

- [x] Wave sampling helper: `game/systems/OceanWaveField.gd` (autoload) mirrors the shader's three-sine function and drives the shared material's `wave_time` uniform every frame, so GPU waves and CPU samples never drift. The shader no longer uses `TIME` — consequence: the ocean is static in the editor viewport. (An earlier note here claimed autoloads don't exist in headless `--script` runs; that's wrong — they are instanced there. Scripts still reach the wave field via `get_node_or_null("/root/OceanWaveField")` defensively for editor contexts.)
- [x] Ship bobbing and pitch: every ship scene now has a `VisualRoot` (Node3D + `ShipWaveMotion.gd`) wrapping Hull/Bow/Mast/ShipVisualBuilder. It samples wave height at bow/stern points (pitch + bob) and port/starboard beam points (wave-driven roll), and divides by the ship's world scale so scaled-up overworld ships bob in world units. Response is deliberately exaggerated (bob 1.5 / pitch 1.8 / roll 1.8) — honest physical amplitudes read as static at gameplay camera distance. Gameplay transforms (movement, sinking snap, collision) stay on the body; the overworld `WaterMarker`/`NameLabel`/`FactionFlag` stay flat on the body deliberately. All node-path consumers were updated (`ShipController`, `EnemyShipController`, `OverworldPlayerShip`, `OverworldNpcShip`, `ShipCombatComponent` mast-break and flame anchoring, and the smoke test's structure assertions). Future visual roll/listing effects (Tier 3) should also target `VisualRoot`, not the body. Signed off in playtest 2026-08-13.
- [x] Heel: implemented in `ShipWaveMotion` so both roll sources compose in one `rotation.z` write. Turn heel leans the hull outward (yaw rate sampled per physics tick from the ship body, max `turn_heel_degrees` 6 at `full_heel_turn_rate` 70 deg/s). Wind heel dips the leeward rail (lateral wind component x sail trim x wind speed factor, max `wind_heel_degrees` 7); overworld NPC ships have no wind system or trim, so they get turn heel only. Both smoothed by `heel_response` 3.0/s and zeroed while sunk. Signs verified headless (leeward dip, outward turn lean); awaiting playtest feel check — the screenshot probe can't steer, so turn heel needs a hands-on turn.
- [x] Sail billow: sails are now subdivided grids (quads 8x6, triangles 21 verts) with per-vertex billow weights, puffed bow-ward (-Z) by `_apply_sail_billow`; depth scales with sail size (`max_billow`) and trim (eased 30% → full 100%). Enemy ships get the default 0.85-trim billow at build time. Flags stay flat quads. 2026-08-14 fix after "sails don't billow" playtest: the rebuilt meshes had **no normals**, so the curve got zero shading and was invisible — `_apply_sail_billow` now computes area-weighted smooth normals, and amplitude went up (quad 0.28 → 0.42, triangle 0.24 → 0.34 of min sail dimension).
- [x] Wakes: `game/scripts/visuals/ShipWake.gd` on PlayerShip/TargetShip/OverworldPlayerShip (NPC wakes stay Tier 5). World-space `ImmediateMesh` ribbon laid by stern distance (auto-stops when the ship stops or sinks), widening and alpha-fading with age, alpha also keyed to lay-time speed (`full_strength_speed`); vertices ride the sampled wave height. Speed-keyed `GPUParticles3D` bow spray. Knobs: `foam_alpha` 0.42, `start_width`/`end_width` 0.45/2.6, `point_lifetime` 2.8.
- [x] Ocean shader upgrades: normals moved from per-vertex to per-pixel (removes faceting), plus a normal-only second wave layer (`detail_strength` 0.9) that fades out between 35–85 view units — up close it reads as sun glints (with `glint_roughness` 0.22, SPECULAR 0.3), at the overworld camera's oblique range it washed the sea milky (caught by probe, hence the fade). Vertex displacement untouched, so `OceanWaveField`'s CPU mirror needs no change.
- [x] Ocean richness pass (2026-08-14, first step toward the North Star): all fragment-stage, displacement untouched. Foam web — two ridged, rotated-octave fbm layers multiplied into lacy filaments, coverage boosted on crests (`foam_scale/foam_coverage/foam_crest_boost/foam_opacity`), sampled at two scales blended by view distance so it's lace up close and chunky patches from the overworld camera. Whitecaps now noise-broken at the edge and textured inside (flat threshold caps read as giant white clouds — probe caught it). Turquoise mottling (`subsurface_color`, `color_noise_scale/strength`, squared so it stays patchy). Foam is matte (roughness 0.85) while open water keeps tight glints. Hard-won: unrotated fbm octaves showed the value-noise cell lattice as blocky rectangles; first-pass coverage (0.32 base) turned the sea into ice floes — final is 0.1 base + 0.28 crest boost against a 0.97→0.5 cut.
- [x] ~~Wave-visibility flecks~~ **Removed 2026-08-14**: the MultiMesh fleck rectangles read as "debris floating in the water" in playtest (user's words). The shader foam web above replaces them entirely — foam is now part of the water surface instead of geometry floating on it. `WaveFleckField.gd` deleted, nodes removed from both scenes. (The *bow spray* particles on `ShipWake` are unrelated and stayed — playtest liked them.)

## Tier 3 — Combat Juice

Readability-first, matches playtest follow-ups. "CANNON GO BOOM" should look like it sounds.

- [x] Cannonball smoke trails (playtest: balls were hard to track; user confirmed 2026-08-14 they expected smoke). `Cannonball.gd` builds a world-space `GPUParticles3D` trail in `_ready`: 52 puffs over 0.85s, near-black holding dark through 40% of life then fading, growing 0.5→1.7x, slight upward drift. Puffs use a shared procedurally generated 64x64 radial-falloff sprite (`Cannonball.puff_texture`, static) — without it the billboard quads showed square corners. On impact/expiry the trail reparents to the ball's parent and self-frees via a child `Timer` (a SceneTreeTimer lambda errored on freed captures during scene teardown — caught by smoke test). Verified with the new `tools/CombatEffectsProbe.tscn` (fires balls across the camera on a loop; reusable for the muzzle/splash work below).
- [x] Muzzle effect upgrade (2026-08-14): `MuzzleFlash.tscn` root is now `MuzzleFlashEffect.gd` (root name kept — the smoke test asserts on it): the original emissive sphere pops as a `FlashCore` child (0.16s), a one-shot 12-puff black powder burst (`EffectSprites.puff_texture()`, shared with cannonball trails) drifts up over 0.8s, and a warm `OmniLight3D` blinks for 0.11s. Recoil: `ShipWaveMotion.add_recoil_roll(side)` — third roll source composed into `rotation.z` (kick `recoil_roll_degrees` 2.2, exponential `recoil_decay` 5.0), called by `BroadsideController` on any successful volley. Gotcha logged: new `class_name` scripts need a `--headless --import` pass before the smoke test can resolve them (same as new assets). Recoil feel needs playtest (probe can't fire broadsides).
- [x] Splash upgrade (2026-08-14): `Splash.tscn` root is now `SplashEffect.gd` (root "Splash" name kept for the smoke test's spawn/range assertions). Pieces: the old cylinder crown stays as a `TemporaryVisual` child using the new `fade_alpha` export (fades via `GeometryInstance3D.transparency` — no material duplication), plus a code-built one-shot vertical spray burst (18 droplets, real gravity) and an expanding foam ring (`EffectSprites.ring_texture()`, ease-out spread 0.6→3.4 over 0.8s while fading). Probe-verified: ring expansion/fade clearly reads; spray is subtle at probe distance, judge at gameplay camera.
- [ ] **← NEXT.** Implement `ShipVisualBuilder.set_fire_state()`: flickering flame scale, ember particles, and a leaning smoke column that scales with fire severity so fires read at gameplay camera distance.
- [ ] Magazine explosion as a sequence: flash → smoke ball → flung plank debris → expanding water shockwave ring.
- [ ] Trauma-based camera shake on broadsides, impacts, and explosions.
- [ ] Replace the translucent black damage overlay with progressive listing (a few degrees of roll/pitch as hull fraction drops) and darkened hull patches.
- [ ] Sinking moment: replace the instant snap with a 3–4 second tween down with roll and foam.
- [ ] Sail damage states: tatter/shrink sails as sail fraction drops instead of only hiding them at mast break.
